# 开发任务

当前优先建设可复用的游戏开发平台，现有方块程序作为技术验证样例。总体边界见 [平台建设总纲](platform-plan.md)，阶段验收见 [实施路线](roadmap.md)，1.6 对照见 [方块项目验收基准](voxel-benchmark.md)。

## 认领与交接

- **阶段** A 为工程底座，B 为创作闭环，C 为可复用生产，D 为全量验证。依赖列是开工条件，阶段用于组织验收，不要求不同领域排成一条队。
- **分工** 「核心」由 Codex 负责选型、接口、安全、兼容性和验收。「实现」待前置契约落盘后拆出可按规格执行的工作。「派发」是低判断批量任务，只有附了当前任务卡且前置已具备时才手动派发。
- 认领时只登记任务 ID、分支或目录和阻塞。可在 [Issues](https://github.com/bailacking/worlddesign-studio/issues) 记录状态；本机派发走 AI 超级终端库和对应工作树。完成后回传 `任务 ID｜产物或提交｜检查结果｜阻塞`。统一在任务分支交付，主分支经 PR 与必需检查合并。
- 任务的目录、接口和检查已可核对才交给执行者。遇到不明确的系统边界，先完成不依赖它的部分，把问题交给 Codex。暂停或额度用尽时保留提交、重现步骤和阻塞状态。

### Codex 暂不可用时

先看「当前可开始」，按任务卡选取独立工作并在工作树内完成。前置契约已有可引用的提交、验收可复跑、改动范围已列清的「实现」任务也可由用户手动转发；执行者遇到规范歧义时提交可核对的例子，把取舍留给后续评审。任何 Agent 都可以在自己的工作树验证和提交，集成仍按 PR 检查。每份任务卡应留下规格链接、可改文件、入口命令和完成标志，下一位接手可直接从提交与日志继续。

## PRJ-01A 清单样例任务卡

按 [固定样例子集](../architecture/project-format.md#固定样例子集) 在 `tests/fixtures/project-v1/` 建两个合法项目：一个只有入口场景，另一个含入口场景引用数据。以第二个为基础，各复制一份并只引入一类错误：版本不受支持、重复 ID、重复路径、路径跳出、缺引用、缺源文件、入口类型错误。重复 ID 用不同的合法路径，重复路径用不同的合法 ID；缺引用仅改变 `refs`，入口类型错误仅将 `entry_scene` 指向数据。路径跳出样例只写清单字符串，测试目录以外不创建任何文件。每个目录名用对应错误分类。根下的 `cases.json` 用对象数组逐项列 `case` 和 `expected`，合法项目写 `ok`。

只改此目录。用 Python 标准库逐份解析 JSON 并核对 9 个样例，检查每个目录与索引的对应关系。提交内容包含样例与索引，交接只回提交、检查结果和阻塞。核心解析器与接口由 PRJ-02 处理。
