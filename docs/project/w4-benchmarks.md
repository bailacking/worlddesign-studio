# W4 内容、资产与运行后端实测

W4 截止北京时间 2026 年 11 月 20 日 22:00。试验在 11 月 16 日完成，以本地 W3 `8041637` 为产品基线。复跑用[样机与命令](../../examples/w4-lab/README.md)，采样环境、文件摘要和指标在[原始结果](../../examples/w4-lab/results.json)。样机独立于 WDS 默认构建。

## 内容生产

取四组原创整数状态，每组 16 个值。区间表示与逐条列值分别输入，用 W3 的规则和校验，在同一版本 Python 上交替运行 15 对。两边加入相同的 8 条 W2/W3 参考记录，生成的 12 条记录及新增的 64 个状态逐条一致。

| 同规格输入 | 输入大小 | 解析、生成、校验和序列化中位耗时 | 首次通过 | 故意损坏后的局部恢复 |
| --- | ---: | ---: | --- | --- |
| 脚本按区间展开 | 201 字节 | 0.216 ms | 通过 | 反向区间定位到 `amber-gate/rule/range`，恢复区间并复验约 0.361 ms |
| 逐条列值 | 400 字节 | 0.210 ms | 通过 | 少列一值定位到 `amber-gate/variants`，补一个值并复验约 0.295 ms |

脚本少写了约一半的输入。两条机器流水线都在亚毫秒级，实测差异很小。正式路线用区间和模板展开重复内容，独特规则与版本特例保留独立 ID 和对应的原版证据。当前输入大小只量化短样例的描述量，完整模型耗时、Token、人工编辑及复核成本留给 W12 的更大样例。

## 美术与声音

「礁灯信使」用同一场景的 A/B 资产执行收集并撤离。A 使用连续参数和程序音色，B 使用手绘像素轮廓、手定造型参数和另一套合成配器。角色体层与灯具层共享坐标。原始素材由[生成脚本](../../examples/w4-lab/assets.py)保存，可重新生成。

| 样本 | 实测 | 后续采用的判据 |
| --- | --- | --- |
| 方块贴图 | 两张 32×32 PNG，对边通过，平铺并进入运行场景。单张生成、写入和校验约 0.7–20.1 ms，本轮首次 PNG 保存含初始化 | 先看正常缩放下的辨识度、邻块拼接和场景层次。平铺素材检查边缘，对应角色与交互区域保留清楚的轮廓 |
| 参数模型 | A/B 分别 56／28 顶点及 108／52 三角面。共用地面和近似高度，均在原生三维视图出图 | 导入前核查三角面、有效索引、法线、UV 及模型尺寸，预览核对轮廓、接地点和碰撞代理的对应关系 |
| 分层角色 | 两套 48×48 角色体层与灯具层均可叠加。脚点 `(24,36)`，挂点 `(34,30)`，灯具比最亮背景高 129–171 个亮度级 | 固定画布和挂点，换装后脚点及碰撞范围一致。检查透明边、动作遮挡和关键标记的对比；较复杂角色增加动作帧审查 |
| 拾取音效 | 0.18／0.26 秒。数字波形起声约 0.18／0.20 ms。无削波，未混音时 RMS 比各自循环音乐高 9.61／7.44 dB | 短事件能与背景区分。样例工程门槛为起声 25 ms 以内、峰值低于 −3 dBFS，混音后仍应能辨认事件 |
| 循环音乐 | 两套 8 秒 WAV 在同一采样率与节拍下生成。端点均为 0，解码成功。逐套生成、保存及数字校验约 346–350 ms | 先核对循环边界、触发位置、动态和音效可辨识性。正式相似度以同样玩法条件下的氛围、节奏和提示功能对照，盲听与真实播放设备补验 |

两套各五类机器检查均通过。第一次加载 A 的初版 OBJ 在 raylib 退出，修补到复跑成功约 170 秒，计入诊断、生成器调整和复验。兼容写法使用显式三角面、UV 和法线。旧候选加载两份修订模型时仍有 VAO 重复上传提示，已留在原始记录。源文件生成耗时与真实编辑、返工、跨设备验收分别记录。

## 运行后端

Windows 11 x64，MSVC 19.44 Release，Ryzen 7 5800H、RTX 3050 Ti Laptop。使用同一份 C++ 场景和绘制顺序，960×540，420 块纹理瓦片、两层角色、相同收集规则。预热 30 帧后采样 240 帧，第 121 帧切换 A/B。两端均在第 208 帧抵达出口，收集 3 个灯，终帧 RGB 最大通道差为 1。

| 试验路径 | 输入状态更新至绘制提交 P50／P95 | 加整帧复制或读回 P50／P95 | 调试与边界 |
| --- | ---: | ---: | --- |
| Qt 6.8.3 QPainter / QImage CPU | 0.125／0.149 ms | 0.363／0.396 ms | CPU 帧可直接保存，适合现有工作台与小场景回退，对照代码测 Qt 绘制路径 |
| raylib 5.5 GLFW / OpenGL 3.3 | 0.071／0.108 ms | 0.968／1.087 ms | 启动日志记录实际 GPU。验证两种 OBJ 出图及四个 WAV 解码。同步 GPU 读回开销高于该场景重绘 |

这些数据来自脚本输入进入场景后的离屏路径，实际按键到屏幕、声卡播放与 Linux、macOS、Web 本轮待测。raylib 上游覆盖多种平台并按 zlib/libpng 许可发布，Qt 路径沿用现有工作台 SDK，发行所选平台及模块的许可检查随包完成。[raylib 5.5 与平台](https://github.com/raysan5/raylib/releases/tag/5.5) · [raylib 许可](https://github.com/raysan5/raylib/blob/5.5/LICENSE) · [Qt 绘制文档](https://doc.qt.io/qt-6.8/qpainter.html) · [Qt 支持平台](https://doc.qt.io/qt-6.8/supported-platforms.html) · [Qt 许可](https://doc.qt.io/qt-6.8/licensing.html)

W5 用 PNG 与 UTF-8 文本复用现有导入预览、提交和来源接口。缩略图缓存以源内容摘要与适配器版本识别，清缓存可重建。W6 把输入动作、固定步进、渲染快照、声音事件分开，以 raylib 继续试验独立播放器，Qt 继续提供工作台与小场景的观察入口。正式选型前复测真实设备上的按键与焦点、较大资产场景及模型导入的错误处理。W7 的构建清单固定修订、运行依赖及资源闭包。
