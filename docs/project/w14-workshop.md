## 场景数据与编辑

场景可选字段 `workshop` 为版本 1，含 `items`、`recipes`、`sources`、`bag_slots`、`chest_slots`。三类映射都按稳定 ID 组织。物品有 `limit`（1–64）和 `tags`，背包和箱子各 1–32 格。掉落暂存在本场景 16 格拾取区。堆叠优先填现有同类格，拾取量受背包容量限制，存取箱子一次 1 个。

- 配方声明 `method`（`craft`、`smelt`、`cook`）和 `output`。材料可精确指定 ID，或以 `#标签` 接受替代材料。`ingredients` 按数量匹配；合成也可声明 3×3 `pattern`，空位填 `null`。运行时支持显式验证九格位置，W14 的工作台与玩家版由所选配方自动配料。
- `station` 引用由另一条配方的 `unlocks` 产生的解锁 ID。材料、布局、设施状态和产物容量全部满足时才扣料和产出。W14 的造炉、熔炼与烹饪即时完成，实体放置式工作设施和烧制计时留待后续。
- 方块的来源键是材料名，`uses=0` 表示每破坏一块按映射生成掉落，回收后可用于配方。已配置的方块放置消耗同一份对应材料。二维来源键是场景实体 ID，距离玩家 36 世界单位内才可采集，`uses` 是单次试玩内的可用次数。样例以独立原创内容演练采集和烹饪，历史《饥荒》运行证据仍沿用 W2 缺证记录。
- 方块 `progress` 随世界修订保存，含 `bag`、`chest`、`loot`、`unlocked`，事务仍走现有场景保存。二维库存独立于源场景，停止并重玩回到初始状态。项目的 `scene.inspect` 可读取初始或已保存的库存。
