# WDS 平台建设总纲

## 产品与当前基础

WDS 是给 AI 与人共同使用的游戏开发平台。平台交付物包括可维护的项目、编辑器、运行时、可复用能力包、面向 Agent 的操作接口，以及可验证的运行与发布工具。创作者可以替换能力包、修改数据或编写逻辑，并把同一项目交给另一位创作者继续维护。

以 [50 周开发计划](50-week-plan.md) 的四项任务验收。两款参考游戏各用 30 分钟从零资产复刻，两款同量级原创游戏各用 60 分钟从新需求制作。四次均交付独立成品和可编辑工程。封存通用工具与能力版本，模型计量和人工接手记录随验收结果保留。 [方块基准](voxel-benchmark.md) · [饥荒基准](dontstarve-benchmark.md)

现有 C++ 基础覆盖构建与测试、内置插件启停、项目管理与恢复。Windows 现代工作台可编辑场景并从保存后的修订试玩，CLI 可导入场景和数据资源。下一批工作包括工作台内导入、通用规则、能力组合与发布链。早期单机方块样例及其项目预设见 [前期原型与验证](prototype-baseline.md)。

## 首个可用平台版本

一个创作者可以创建、打开和验证项目，导入资源，用场景树和属性面板编辑，组合至少一个可复用玩法，启动并停止试玩，保存、重开和导出。另一个创作者可在新工作区打开同一项目并继续编辑。Agent 能列出同样的能力、读取项目状态、提交带修订前置条件的修改、查看差异、运行检查，并生成简短的交接摘要。

以两个不同项目验证这套工作流。一个可以使用方块能力包，另一个使用同一平台的场景、属性、规则和发布工具，创建一个与方块无关的互动项目。两个项目都应能交给人继续编辑并运行，工作流共用相同的项目、操作和发布契约。

## 系统边界

| 工作流 | 平台拥有的数据或接口 | 依赖方向 |
| --- | --- | --- |
| 项目与资源 | 清单、版本、稳定 ID、资源引用、迁移与恢复；源文件和生成物各有位置 | 文件系统适配 → 项目存储与资源索引 |
| 共享操作 | 能力发现、查询、修改、修订、预览、执行结果、撤销和诊断 | GUI、CLI、Agent → 操作层 → 项目与领域服务 |
| 编辑器 | 项目入口、场景树、资源面板、属性、逻辑编辑、试玩和日志 | 编辑器通过共享操作读取与修改项目；试玩用已选修订 |
| 游戏运行时 | 场景、实体、组件、系统、生命周期；渲染、输入、物理、音频等后端 | 游戏逻辑依赖能力契约；平台细节留在适配层 |
| 玩法与内容 | 可验证的数据、版本化模板、能力包、示例、测试及迁移 | 项目声明所需能力；发布解析运行依赖 |
| AI 工作流 | 能力说明、最小项目上下文、授权、预算、预览、验收和交接 | Agent 经公开操作访问项目；模型可替换 |
| 发布与协作 | 构建计划、资源产物、运行依赖、打包、回滚、Git 协作和平台证据 | 发布读取指定项目修订与依赖锁定信息 |

### 先约定的接缝

- **项目模型**：先确定项目格式版本、资源身份、路径、引用和读写边界。运行存档、编辑源文件、缓存和发行产物拥有各自的生命周期。旧样例保留可读路径和迁移用例。
- **操作模型**：每条操作声明稳定 ID、版本、输入、前置条件、是否改变项目及错误。修改请求携带预期修订。预览不写盘，提交返回受影响资源和新修订。GUI、CLI、Agent 共享校验和提交。
- **领域数据**：组件类型及可编辑字段通过同一份元信息暴露给编辑器和 Agent。运行时可以为实时路径采用不同存储，需保持项目语义一致。
- **运行与发布**：编辑器启动可追踪的试玩会话。试玩默认使用独立运行状态。发行输入由项目修订、目标平台、能力包及资源组成，必须可以复现与诊断。
- **技术选型**：C++ 核心延续现有基线。编辑器框架、渲染后端、正式序列化、脚本、插件 ABI 和依赖管理在各自调研任务通过后锁定。正式实现服从 [设计原则](../product/vision.md) 与 [技术评估](../engineering/technical-evaluation.md)。

## 推进顺序

1. **A · 工程底座**：项目模型与共享操作先合流，建立可自动核验的兼容性与数据恢复用例。
2. **B · 创作闭环**：编辑器打开与编辑项目，运行时从项目读场景，CLI 可重复相同操作，导出可独立启动。
3. **C · 可复用生产**：能力包、模板、脚本和可视化、资源导入、跨平台、Agent 能力发现与验证逐步接入。
4. **D · 全量验证**：并行核对两款参考行为和内容，关闭平台缺口，再用四项限时任务检验创作、发布和人工接手。

逐周交付和验收以 [50 周计划](50-week-plan.md) 为准。接口、依赖与认领范围见 [任务表](development-tasks.md)。工作流间可并行，接口选择、兼容性、数据安全和集成由 Codex 负责。
