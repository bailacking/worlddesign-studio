# W15 红石、联机、跨世界与角色分层

约定截止为北京时间 2026 年 11 月 20 日 22:00，以 W14 `481603f` 为基线。W15 试验在 11 月 18 日完成 Windows 本机验收。 [构建与复跑](../../examples/w15-lab/README.md) · [实测数据](../../examples/w15-lab/results.json)

## 红石逻辑步

`circuit.replay` 读取最多 64 个有输入连接的节点和 256 步。每步先应用拉杆事件，再冻结信号快照，随后按节点 ID 处理更新。线材每次传播衰减 1，灯与中继器使用二值强度。中继器的排程保留到期步和候选信号，候选在到期前失效时取消。回执带时间、节点、相位、前后值及输入来源，可以从灯回查传播链。

双分支汇入同一中继器的样例中，两线在第 0 步按 ID 更新，第一次排程的第 4 步信号被取消，灯在第 8 步亮并在第 15 步灭。反转节点输入顺序后时序相同。无效连接定位到 `/input/nodes/lamp/inputs`。本轮定义了 WDS 样例相位，原版方向、比较器与特殊更新仍按正式参考线验收。 [线路请求](../../examples/w15-lab/circuit.json)

## 权威会话与存档

试验服务器绑定 `127.0.0.1`，使用每行一条 UTF-8 JSON 的 TCP 协议。帧带 `v: 1` 和 `type`。客户端先发 `hello`，用服务端返回的票据续接同一玩家；`snapshot` 返回已提交的修订、当前世界、两张地图各自的坐标、玩家摘要及本人的库存。服务端用当前玩家位置检查一步移动与射线采矿，掉落、拾取和合成复用 W14 规则。

动作帧提交 `seq`、`revision` 和 `command`。过期修订拒绝写入；已提交的最后一个动作重复发送时只确认，序号相同而内容不同则报冲突。每次成功变更先用 `QSaveFile` 提交完整存档，再广播新快照。单文件记录两个世界、各自的位置、库存、解锁和最近动作序号，且关联初始化工程和材质指纹。一个存档同时只允许一个服务端写入。

两个本机 TCP 客户端接收同一修订的服务器广播。测试让 A 在地表造炉后进入洞穴采矿，B 留在地表；模拟保存失败，确认旧世界与修订仍可读。随后让 B 收到提交，再切断 A 未读回执的连接，终止并重启服务端。两客户端各用原票据恢复，重发 A 的动作不会重复执行。A 返回地表时两张地图的摘要、各自坐标 `[13,17]` 和 `[11,17]`、2 矿石和 1 炉均通过校验。最终修订 16。当前是本机回环、小型世界、完整快照和固定高度移动的试验，正式局域网与独立服务端交付在 W29。

## 2.5D 分层换装

预览布局使用等距地面和栏杆，角色本体以固定脚点落地，附件按自己的挂点对齐角色同一位置。提灯使用 48×48 图，行囊使用 20×20 图。换装不移动身体和脚点，前后切换会调整栏杆遮挡。比较程序检查两张装备在同一投影挂点显示、换装前后身体采样保持，Windows 原生窗口实际切换两种装备及栏杆前后。 [可编辑外观描述](../../examples/w15-lab/assets/look.json)
