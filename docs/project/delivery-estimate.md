## 估算方法与协作情景

先按能够单独验收的工作包估剩余工作量。短区间假设复用现有接口和成熟库，长区间包含常见的兼容问题与实现返工。对跨包集成、发布验收和接口变化再预留 25%～35%，全量约 **625～1,215 个等效工程工作日**。按每周 5 个工作日和平均 **1.8 条有效并行线** 粗算约 **69～135 周**，给最初导入与后期集成留出串行窗口后，完整范围取 17～32 个月。有效并行线指实际出成果、复核和集成后还能稳定推进的工作量，包含主开发线。任务分给多个 Agent 并不能自动把同一接口设计和最终验收变成并行工作。

| 情景 | 可持续条件 | 首款 Windows 游戏 | 完整 1.6 参考目标 | 已明确的完整产品范围 |
| --- | --- | --- | --- | --- |
| 高并行 | 约 2.6 条有效并行线，独立模块和素材能持续交付 | 约 8～15 周 | 约 11～21 个月 | 约 13～25 个月 |
| 基准 | 平均 1.8 条有效并行线，Codex 负责关键接口和合并 | 约 10～19 周 | 约 14～28 个月 | 约 17～32 个月 |
| 主要靠一条开发线 | 平均一周 5 个等效工作日 | 约 4～8 个月 | 约 25～48 个月 | 约 29～56 个月 |

实际日历受维护者可用时间、跨平台设备、插件选型和原版证据覆盖影响。基准情景没有用已完成的 UI 小任务速度推算玩法和联机。每完成一个里程碑，用已合并或已验收的工作量重新核算吞吐；若连续两周低于假设，先更新日历区间，再决定是否增开独立工作线。上下限是规划情景，尚未积累足够数据来给出统计置信区间。

## 哪些工作决定工期

1. **先交付首款游戏。** 导入审查与工作台接线完成后，图片/文本适配、能力包清单、最小播放器可以并行。连成可玩产物仍依赖运行时读取正确的修订、资源与锁定依赖，并在独立目录启动。
2. **再扩展可复用创作。** 稳定场景与行为数据后推进 3D、音频、规则编辑和模板；AI 操作沿同样接口执行，测人工接手。首个方块场景也用这条路径。
3. **完整参考项目分系统交付。** 先冻结 1.6.4 主参考与系列差异口径，早做资料与许可盘点。区块和方块行为稳定后展开材料、合成、地形和环境。生物与维度、红石和多人可错峰并行，最后必须做组合交互和真实存档复核。
4. **测 10 分钟前先建立对照。** 固定同一模型、机器、需求、预装能力与验证清单，从需求收到到产物与可编辑项目同时交付都计时。记录实际输入输出 Token、工具等待、重试、失败和人工干预。请人类修改一项内容和一条规则，并再次运行、保存重开、导出。[方块项目验收基准](voxel-benchmark.md)
5. **跨平台按证据放行。** Windows 是首发目标。Linux 默认 CI 只覆盖核心构建路径，编辑器和发行包需实机核验。macOS 需要真实环境确认。Web 试玩估入，完整 Web 编辑器与远程宿主是候选；若后续要求齐备，暂预留 **3～7 个月**的新增工作窗口。Git 深度整合、托管服务和第三方插件生态规模也由实际范围决定。基准工期已计 Git 差异与协作基础、SDK 和插件发行流程。
