## 特例取证及规则拆分

1. 普通内容用范围、模板、稳定 ID、引用校验批量生产。统计报告分别列目录记录、展开变体和实际可互动条目。版本特例独立保存来源、适用范围和差异字段，按 ID 局部修补。
2. 在原版证据补入 [W2 台账](w2-references.md#条目分类记录与证据等级) 时先锁定构建和起始状态。方块从 `MC-BLOCK-001` 的 0–4 充能与上限、以及重生前后消耗入手。制作从 `MC-CRAFT-001` 的横排、旋转及消耗分开记录。数据证据先固定输入和配方，动态步骤继续留在运行验收。
3. 《饥荒》`DS-CRAFT-001` 记录有无关键材料、有无科技权限两组条件，`DS-ROG-001` 分开记录初始季节设置与后续转换。目标历史构建仍缺运行证据，取得可运行版本后按台账补实测。 [方块基准](voxel-benchmark.md#w2-逐领域对照) · [饥荒基准](dontstarve-benchmark.md#w2-逐领域对照)
4. 场景输入、条件、状态变化、效果和保存各留可检查的结果。W13 的地形覆盖生成、跨区和保存；W14 的配方先校验材料与排列，再处理产物和消耗。部分布局用槽位约束，重复原料按数量检查。每个特例有一条孤立用例和一条跨系统组合用例，现场只复跑受影响的规则及必要交互。
