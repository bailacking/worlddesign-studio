# 实施路线

## 当前阶段

WDS 已实现 C++ 的 M0 基础程序，可在 Windows x64 验证插件启停、GUI 与 CLI 共享改名操作和保存恢复。各阶段依验收证据推进，首个可玩沙盒仍待开发。

## 项目基础

维护产品范围、主题架构、贡献规范、许可、研究与验证标准，明确首个原型的任务。项目文档与公开讨论集中在 [GitHub 仓库](https://github.com/bailacking/worlddesign-studio)。专门的社区服务和私密联络方式仍在筹备。

## 最小基础程序

先评审 [首轮技术规划](../engineering/technical-evaluation.md)，完成 C++ 工具链调研和契约约定，再分配实现工作。第一轮验证精简运行基础、至少两个试验插件、最小 GUI 与 CLI 的共享操作，以及项目保存和恢复。检查缺依赖、版本冲突、初始化失败和禁用清理。

阶段验收要求可复现启动步骤、固定环境、等价操作结果、失败用例和明确限制。任务的依赖、分工和验收条件见 [开发任务](development-tasks.md)。

## 首个可玩游戏

制作 3D 方块沙盒，贯通地形、移动、放置与破坏、资源管理、保存重开和 AI 参与修改。内置 AI 产品化不是本阶段必要前置，外部工具可以验证操作闭环。

至少在一个明确平台完成可复现的独立运行产物，展示变更、实际运行结果和恢复路径。记录性能测量环境，不预设未经验证的指标。

## 创作能力扩展

逐步完善 2D、3D、动画、物理、音频、网络游戏、可视化逻辑和资源编辑。按已评估的方案发展版本管理；通过小型可玩样例验证各领域，而非以一个沙盒代表全部能力。

重点验收共享逻辑、资源身份、多形式编辑、并发冲突、调试及平台差异。

## 插件生态

建设插件开发工具、契约文档、组合分享、发现机制、用户评价和兼容性报告。独立贡献者应能按文档制作插件，用户能替换能力并恢复环境。兼容性规则从最小基础程序开始实施，此阶段扩展规模和服务。

## 高度自动化创作

完善内置 AI、自然语言制作、自动运行检查与修复、跨资源生产流程。通过明确任务集记录成功、失败、成本和人工接管；用户能够暂停、查看和继续维护成果。

一次成功演示不构成“可自动制作任意游戏”的验收。质量标准见 [质量与验证](../engineering/quality.md)，实现选择见 [技术评估](../engineering/technical-evaluation.md)。
