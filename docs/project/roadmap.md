# 实施路线

## 当前阶段

WDS 以通用游戏开发平台为交付主体。已验证的 C++ 工程、插件、资源操作和方块样例见 [前期原型与验证](prototype-baseline.md)。当前优先交付能编辑、保存和试玩真实项目的 [桌面工作台](../architecture/workbench.md)。阶段任务见 [开发任务](development-tasks.md)，多人认领与合并顺序见 [并行开发计划](parallel-delivery.md)。

| 阶段 | 主要交付 | 进入下一阶段的证据 |
| --- | --- | --- |
| A 工程底座 | 项目清单、资源身份、版本迁移、事务恢复、共享操作协议及桌面编辑框架选择 | 合法与异常项目可复跑验证，旧数据有迁移或保留路径，预览不修改项目 |
| B 创作闭环 | 编辑器工作台、场景和属性、资源导入、试玩、共享 CLI、Windows 导出 | 同一项目可从 GUI 和 CLI 编辑，保存重开一致，导出后可独立运行 |
| C 可复用生产 | 版本化能力包和模板、逻辑与调试、AI 工作流、跨平台和生态工具 | 方块项目与非方块项目共享编辑发布流程，另一个创作者可继续修改 |
| D 全量验证 | 1.6 参考项目、全量能力矩阵、时长和 Token 对照、编辑交接与发布验证 | 参考范围内每项都有证据，交付可运行与可编辑项目，报告差异和指标 |

## 验证项目如何影响平台

《我的世界》1.6 参考项目逐项暴露平台缺口。每个缺口判断归属：通用需求进入项目、编辑器、运行时或发布接口，领域玩法进入可复用能力包，普通内容进入参考项目。完成后通过 [方块项目验收基准](voxel-benchmark.md) 验证全量内容与行为和 10 分钟低 Token 目标。

开发顺序、系统边界及首个可用版本见 [平台建设总纲](platform-plan.md)。自动检查与人工验收见 [质量与验证](../engineering/quality.md)。每次交接记录分支或产物、已跑检查和阻塞，远端主分支经 PR 和必需检查合并。
