## 条目分类、记录与证据等级

后续参考补证按[参考游戏先查资料再实测](../engineering/quality.md#参考游戏先查资料再实测)执行。先查目标版本资料，记录证据能解决的问题，再补最小的动态用例或验收明确要求的实跑。

- 每条记录用 `MC` 或 `DS` 加领域及三位流水号。领域沿用两份基准的八个分类。ID 分配后保留，变更版本、平台或模式写入证据字段。跨领域场景引用主条目，覆盖分母只计一次。
- 每次执行记录版本与构建指纹、平台和模式、种子或起始存档、步骤、预期、参考实际、WDS 实际、证据位置、结果、责任人和依赖任务。源文件无法取得或结果未执行时写明原因和补证条件。
- **原版实跑**记录固定输入下的行为、数值、状态变化和日志。**原版数据**指从已校验原版发布包直接查看的数据，或运行其数据生成器得到的报告。只适用于这些数据能直接证明的事实。
- **官方文档**支持版本发布、机制的声明及历史变化。较早版本公告用于形成可检验的预期，目标构建的实际状态另行确认。较新版本观察可用于排查版本变化，原始结果和观察版本同时保留。
- **线索**包括未固定版本的资料或未复核现象。**缺证**用于安装、运行、来源或结果尚不可验的条目。覆盖统计逐领域列出应验、已执行、通过、失败、缺证和经确认的范围外，缺证保留在应验分母中。W2 样例是按领域抽样的起点。

内部验收可查看官方发布包、公告和授权取得的原版，仓库记录来源、校验值、观察和步骤。原版素材、安装文件、可还原数据包及账号资料留在仓库外。各次 30／60 分钟任务仍执行[零资产和计时要求](50-week-plan.md#零资产计时与人工接手)。

## 原创盲题如何评到同量级

独立验收人先用两款参考各一份行为矩阵确定难度基准，再为方块题和非方块题分别冻结可复跑的目标数量、必过场景和测量条件。题目首次揭晓时开始计时，每题含一项未演练的规则组合。两类作品按各自题目统计，无法运行或缺证的项目在对应维度记 0，达到部分要求记 1，达成冻结目标记 2。

| 维度 | 冻结题目时的量化依据 | 判定所需证据 |
| --- | --- | --- |
| 内容 | 可实际获取、使用且在玩法上有区别的条目数，按功能去重 | 核对目录及采集、制作、使用路径，至少覆盖普通和例外条目 |
| 世界 | 机制有区别的区域、环境转换与持久化状态 | 固定种子或初始存档，走区域进入、退出、保存重开的路径 |
| 独立机制 | 具有独立规则与可观察结果的系统数量 | 为每个计数系统跑正常路径和一个边界条件 |
| 跨系统联动 | 不同系统间可复跑的状态传递及顺序 | 同时校验事件前后状态，覆盖一项现场揭晓的组合 |
| 成长 | 可达的解锁节点、阶段和影响后续策略的选择 | 从初始状态到约定里程碑，核对资源消耗、解锁与回退 |
| 稳定性 | 固定设备上的启动、代表流程、保存与失败恢复标准 | 在封存包上复跑，有异常时记录数据是否可恢复 |
| 可编辑性 | 创作者接手续编所需入口与可修改对象 | 另一位创作者修改一项内容和一条规则，保存、重开、试玩并重新导出，在另一台机器运行 |

正式签收要求限时内交齐成品和源工程，七维分别达到冻结目标，并通过未演练组合与续编验收。W2 确定评分方法和样例，后续依据两份完整行为矩阵和原版实测定各维数量。记录模型、Token、等待、重试和人工干预，以同模型从零任务做对照。
