# 方块项目验收基准

## 范围与参考

长期目标是用 WDS 快速一比一复刻《我的世界》Java 版 1.6 系列的完整玩家可见内容和行为。**暂以 1.6.4 为主参考**，用 1.6.1、1.6.2 差异补充系列内变化；最终验收版本可由发起人调整。Mojang 的版本清单可核验版本身份，不能据此推断完整玩法清单。[官方版本清单](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json) · [1.6.4 版本元数据](https://piston-meta.mojang.com/v1/packages/b71bae449192fbbe1582ff32fb3765edf0b9b0a8/1.6.4.json)

以可观察的系统、内容种类、参数、交互和边界行为定义对照。记录原版外观、音频、界面或兼容需求时，单独标明验证条件与所需资料。WDS 仓库内的代码和素材应可独立分发，参考来源记录版本与证据位置，资产授权与复用范围在发行前核对。

## 全量矩阵的范围骨架

REF-01 已整理 [1.6 参考资料目录](../research/minecraft-java-1.6-reference.md)。目录记录来源和证据缺口，供 REF-02 逐项核对原版行为。

下表是待逐项盘点的范围，不能作为已经完整的参考清单。完整清单需要统计可验证条目、已验证条目、缺证和不适用项。任何不适用项都要写明原因并确认，不能用缺证替代覆盖。

| 领域 | 要逐项核对的对象 | 对应平台任务 |
| --- | --- | --- |

| 方块与环境 | 全部方块及状态、放置/破坏/掉落、液体、火、重力、光照、农作、红石、活塞、轨道 | VOX-02、VOX-05、VOX-07 |

每项验收记录包含稳定 ID、版本、模式、前置数据、操作、原版观察、WDS 观察、证据、阻塞能力和状态。重复条目按数据批次验证，交互与边界保留实际场景。关键能力缺失进入平台任务页，普通素材及配置进入参考项目。平台能力应另在非方块项目或独立契约测试中验证。

## 计时与编辑交接

1. 固定参考范围、需求、机器、模型、工具权限、WDS 版本和已安装能力包。用空工作区开始，记录预装内容及版本。
2. 分别用 WDS 与从零方式执行同一需求。自收到需求开始，计入模型推理、工具等待、失败重试、运行检查和生成交接。保存实际输入与输出 Token；无法取得的字段标为未测。
3. 在同一机器和规则下验证可运行交付物，逐项核对已声明行为。检查项目源码、规则、资产和依赖是否随项目交付。
4. 由人类在编辑器中更改至少一项内容和一条玩法规则，运行、保存重开，再次导出。记录是否需要回到 Agent、是否要求重写引擎或丢失内容。

先用小任务测量方法和可重复性，再扩到全量参考目标。10 分钟目标只以全量验收结果判断。Token 目标待同条件从零对照后确定并公开。
