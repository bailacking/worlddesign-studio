## 运行与编辑契约

- 一个场景可引用 ID 为 `expedition` 的 `data` 资源。其版本 1 文档声明区域、地形种子、行动站点、路线依赖、配方与生存参数。顶层 `icons` 指定各类站点的默认图标。站点可用 `icon` 覆盖默认值。图标是普通 PNG，由项目清单的 `expedition` 引用并随项目打包。
- 原创远征使用格网动作。一个成功动作推进一步，失败动作保留状态。回放逐步给出损伤原因、状态值、库存、角色所在地区和各地区坐标。输入、种子和工程修订相同时可重复比较。
- Windows 运行包在包目录中维护一份 `expedition.save.json`，保留工程标识、修订、规则数据指纹和至多 4,096 个已成功的动作。保存时先写临时文件，再原子替换最近的完整版本。原生播放器持有单进程锁并在保存成功后接收新状态。同一修订的重开会重放动作，版本或规则变更后的存档会被拒绝。该测试覆盖进程中断。
- 恢复锚点可以设置 `capacity`（1–20），缺省为 3。选择另一个锚点时从其首次充能开始。已充满时保留资源和当前行动步。
- 项目字段操作可预览并修改顶层整数。提交前检查参数和引用，文档不可运行时返回字段位置。使用 `expedition.replay` 立即复跑修改后的工程。Windows 发布组件需声明 `expedition_format: 1`。
- 两类原创示例共享同一个 C++ 运行模块和发布入口。体素示例保留可在工作台打开的 W17 入口场景，远征使用等距块地图。二维远征使用俯视地图。数据中的远征规则可通过 CLI 和普通文件编辑。

## Windows x64 实测

两条原创路线分别完成 39 和 48 个成功动作。Windows 工作台与核心共 20 项回归通过。四轮试演共验证 16 份独立包，含两个项目的修订 0 和修订 2。验收从成品目录外启动播放器，并把环境变量 PATH 限制为系统目录。

W24 高负载样本包含 2 个工程、9 个区域、475 个站点、37 项配方、163 份实际加载的 PNG 和 36 个地形色。额外的 432 个站点组成 144 条补给链，每条都有采集、不同材料数量的可选配方、交易和凭券进入的营地。
