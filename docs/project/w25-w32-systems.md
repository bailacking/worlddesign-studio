## W25 电路与生存契约

- `circuit.replay` 仍使用按输入、快照、更新排序的离散逻辑步。比较器的第一个输入为主信号，后续最多两个输入提供侧信号。可选择比较或者减去最强侧信号。输入的 `checkpoint: true` 返回当前布局、下一步编号、各节点强度和排队中的中继变化。用同一布局和 `resume` 继续运行，动作时间相对本次请求，回执仍是从最初开始的绝对步编号。
- `scene.voxel.actuate` 默认在触发节点上升沿按 `dx`、`dz` 推块，可选 `capacity` 将容量设为 1–8 块。`motion: "sticky-pull"` 在下降沿把 `x`、`y`、`z` 上的一块沿反方向拉回一格。可选 `requires_high` 在触发步末检查门控节点，并支持从电路检查点恢复其状态。预览返回触发步和移动数。无触发、目标格占用或容量不足时保留原工程。
- 可选 `plot` 地块定义种子、产物和生长步数。播种后即参加当步生长。全年受统一季节驱动，冬季停长，非海岸区域在炎热季也停长。所有区域的地块随成功动作更新。保存重开按动作回放恢复。
- 远征物品可声明 `spoilage` 的到期步数和替换物。每份批次保留自己的到期步数，移动时保留原批次，只有到期时间相同的批次才合并。到期后的物品可以在原位置按原数量转换。
- 带 `priority` 的烹饪配方接受明确提供的 1–8 份食材。必须匹配全部食材并具备所需工位，优先级高者优先，同级按配方 ID。失败保持库存、回执和时间不变。新的 Windows 运行包能力为 `survival_format: 1`，导出时检查。

试验场和复跑命令见[风园试验场](../../examples/w25-lab/README.md)。参考资料先核对 Mojang 2020 年比较器说明，其中支持比较和减法用例，地形、相邻方块的取值与原版时序仍待对照。Klei 的 `198251` 公告只确认发布构建及该次修补，历史运行证据沿用此前缺证记录。本轮回归测量 WDS 自身的原创规则。 [Mojang 比较器说明](https://www.minecraft.net/es-es/article/taking-inventory--redstone-comparator) · [Klei 构建公告](https://kleiforums.com/game-updates/sw/198251-r159/) · [前期参考台账](w17-w24-reference-audit.md)

## W25–W26 大帅的方块世界

`workyard-v1` 以种子地形为基础，加入有承托和净空要求的轨道，以及按轮推进的水与火。矿车可跨越 X=15 到 X=16 的区块边界并停在断轨前。水先下落，再在有承托时向四邻衰减扩散。火可点燃邻接木材，流入的水同轮熄火。项目操作、工作台与 Windows 播放器共用 C++ 规则。水火提交使用源工程修订检查，Windows 发行元数据要求 `voxel_dynamics_format: 1`。 [试玩与回归](../../examples/voxel-workyard/README.md)

`workyard-v2` 加入熔岩源、三级熔岩与固态玄武岩。水和熔岩从同一回合的起始状态计算传播。两种流体流入同一格，或熔岩与已有水块面邻接时，该处冷却。熔岩和玄武岩随工程保存。跨区块回归对比预览、提交和重开，并保留 `workyard-v1` 的读取覆盖。导出新试验场要求播放器声明 `voxel_thermal_format: 1`。 [大帅的方块世界](../../examples/voxel-workyard/README.md)

大帅的方块世界有一条向南弯折的支轨。`scene.voxel.cart` 可用 `directions` 指定每格方向，跨区块转弯后遇断轨便停止。水闸样例用电路上升沿把石块移入相邻空格。闸关时水留在上方，开闸后下一轮落入原闸位。

`workyard-v3` 可行驶在相邻且高差为一格的轨道上。矿车优先选择同高且有承托、有净空的相邻轨。升降连接还要求较低轨道的上方两格为空。岔道回归从 X=16 上到 X=15 再降到 X=14，并验证低顶棚阻断双向通行。CLI、工作台和独立播放器共用行驶规则。`workyard-v1` 和 `workyard-v2` 继续按平轨行驶。导出 `workyard-v3` 要求发行元数据声明 `voxel_grade_format: 1`。

## W31 双工作树验证

`scene.merge` 接收当前修订、公共基线 `base_directory` 和 `base_revision`，以及来件的 `other_directory` 和 `other_revision`。按入口场景的资源 ID 查找三个版本，按实体 ID 合并非重叠字段。预览检查是否可合并，提交生成可由 `scene.restore` 撤销的新修订。双方修改同一字段为不同值、双方存在不同的实体顺序改动时，响应列出冲突路径并保留原工程。

`project.merge` 通过 `project request DIRECTORY` 接收同一组修订和目录，加上 `input.resources` 中 1–8 个现有资源 ID。按三份清单中的 ID 查找内容，写回当前清单登记的路径。场景和数据 JSON 合并不同字段的修改。图片和文本可以采纳一侧修改或相同的修改。发生冲突时，`conflicts` 列出资源和字段路径，`versions` 提供值摘要；图片和文本以内容指纹区分。请求可携带预览返回的 `merge_token` 和 `resolutions`，每项填写 `resource`、`path` 与 `side`，其中 `side` 选择 `current` 或 `incoming`。预览后任一选中资源或清单变更，提交会返回 `merge_input_changed` 并保留原文件。单文件上限为 1 MiB，一批修改的旧内容与新内容合计上限为 3 MiB。

`preview` 返回会变更的资源 ID，`apply` 只递增一次修订，并返回含有逐文件新旧字节的 `change` 对象。将每个资源的 `before` 和 `after` 互换，并在新修订上调用 `project.restore`，可预览或提交整批撤销。WDS 写入同时发生时，只有持有同一工程写锁的进程能提交。写入中断后使用 `project.recover` 检查清单和全部相关资源，根据清单修订恢复到完整的旧版本或保留已提交的新版本。资源出现第三种内容时，恢复保留文件与日志，待人工确认。

`project.diff` 使用 `read` 模式、当前工程修订及 `other_directory`、`other_revision`，对比相同项目 ID 的两个目录。输出按资源 ID 标出路径移动、引用变化、源码格式变化、JSON 字段差异和二进制内容变化。场景实体的字段路径按实体 ID 给出。输出包含变更位置和类型，二进制保留在工作树内。

`project_collaboration` 在临时 Git 仓库中合并两个真实工作树。一个分支更改场景速度和 PNG，另一个移动规则文件并改规则值，同时改同一份 PNG。合并时从 Git 暂存区提取冲突两侧，给第二张图分配新资源 ID，再用 WDS 打开工程并用语义差异核验。回归还覆盖三个资源一次合并、整批撤销、资源级冲突、部分写入后的恢复以及同一修订的并发提交。

工作台的「项目 → 合并资源」依次选择共同基线和来件工程，再选择要预览的资源。「选择冲突版本」可对不同字段保留不同一侧，并再次预览后提交。也可保留本地冲突资源、继续预览其余资源。回归在同一个场景中采用来件速度和本地位置，同时保留本地图像并合入无冲突的规则变更。

## W26 区域环境

`scene.landscape.environment` 在场景当前修订采样坐标和游戏步编号，返回确定性的天气、头顶是否开敞及直射光。`light` 还计入沿相邻空隙传播的天光、火光和熔岩光，每跨一格衰减一级。测试把屋顶从第 15 列移到第 16 列，确认直射与侧向照明随遮挡改变。夜间熔岩仍能照亮邻格，冷却生成实心玄武岩后该格不再传光。

通过 `scene.voxel.dynamics` 提供 `weather_tick`，可按同一时间点的种子天气推进水火。雨和暴雨会熄灭露天火格，有遮挡的火可点燃相邻且有遮挡的木材。`weather_extinguished` 单列因降雨熄灭的火格数量，结果也计入 `extinguished`。省略时间点则沿用原有水火规则。跨区块回归对比晴、雨和暴雨，验证预览时文件保持原样，并通过电路移开屋顶后继续推进，确认原本受遮挡的火格熄灭。

工作台与独立 Windows 播放器用 **L** 切换昼夜、**P** 预览下一天，视口显示和渲染同一时刻的天气。`workyard-v3` 的 **F** 按该时刻推进火势与流体。`workyard-v1` 和 `workyard-v2` 的 **F** 保留原有规则。安装后的工作台回归实际发送 **P** 和 **L**，对照晴天、雨天、夜间和切回白天的场景画面。

带种子地形的工作台视口默认预览白天，按 **L** 切到夜间或切回白天。视口按已载入区块缓存光照，跨区块、编辑方块、推进流体或切换昼夜时更新缓存。回归核对逐格查询与渲染缓存的光照等级，以及昼夜地表颜色差异。

可选的 `climate` 按季节声明四段 `wetness` 和 `heat` 变化量，可另设 `eruption` 的周期、提前预警步数、活跃季节和伤害。原创建例中，角色在第 4 步收到喷发预警，第 6 步受喷发伤害。带 `venom` 的敌人反击后施加中毒，中毒随玩家旅行。解毒使用带 `antidote` 标签的物品，失败尝试保留时间与库存。湿热、喷发、中毒的回执依执行顺序发出。涉及此配置的 Windows 包需声明 `exposure_format: 1`。

## W27 加工和耐久

原创远征装备可定义 `inscription`。铭纹的 `force_bonus` 增加伤害，`guard_bonus` 降低受到的反击伤害。配方方法 `inscribe` 使用已解锁的加工站，输出单件带铭纹的耐久装备。在背包中以攻击、护持、稳定 ID 的顺序选择出战装备，每次成功攻击扣一次耐久。Windows 发行包需声明 `inscription_format: 1`。

原创建例先制作炉具，再以 `brew` 配方酿造并解锁强化，最后以 `upgrade` 制作耐用武器。带 `durability` 的远征物品单件成堆。保存和重放按成功动作恢复磨损，失败攻击不消耗耐久，两次有效攻击耗尽样例武器。Windows 包需声明 `processing_format: 1`。

`expedition.replay` 可加 `checkpoint: true` 取得与现有远征存档相同结构的检查点。将检查点放入另一条请求的 `input.resume`，同时在 `actions` 提交后续动作。工程路径可以变更，项目 ID、修订和规则包内容必须匹配。回归将「芦风博物队」从洞穴、遗迹、修船甲板与岛屿分段交接，再依照留存位置返回海岸，逐步对比同一路线的库存、船况、角色状态和季节。

## W28 分支章节

「铜脊接力」的生成器支持 `--mode journey|build|trial|survey`，为同一方块远征项目生成不同规则包。远征数据的 `rule_pack` 指向资源清单中已声明并由远征引用的 JSON 数据资源。规则包以 `version: 1` 和 `mode` 为必填项，可选 `deny` 命令名单、`season_ticks` 和 `hunger_interval`。拒绝的命令保留原状态和时钟。

| 模式 | 默认行为 |
| --- | --- |
| `journey` | 保留探索、采集、制作、战斗和原救援规则。 |
| `build` | 可用 `supply` 取出一件目录物品。饥饿值和生命值保持原值或恢复。 |
| `trial` | 使用常规生存机制，禁止 `revive`。 |
| `survey` | 可移动、跨地区勘察，不推进时钟或消耗库存。 |

`expedition.replay` 的 `play_rules` 返回生效的资源 ID、模式、可用命令和时钟参数。存档绑定规则包内容，包内容变更后须从匹配版本重开。旧项目继续采用原规则和原存档身份。Windows 发行包声明 `expedition_rules_format: 1`。

`expedition.recipes` 在指定修订上读取配方、产物、物品标签、取得地点和工位解锁关系。可从炖食追踪到炉灶、解锁炉灶的配方、种植地和可作为香料的物品。每条配方的 `command_allowed` 反映当前模式或规则包是否允许制作或烹饪。执行时仍检查角色所在位置、库存和工位状态。四种模式均按各自规则回归。

`reachable_stations` 列出从已开放工位出发，经当前模式允许的配方可以解锁的工位。工作台据此提示工位已开放、待解锁或当前模式无解锁路径。多级加工和循环依赖都可查询，闭环加入可用起点后会显示为可达。执行条件另外由实际库存、选定配方和位置决定。

工作台打开风园后，选择「场景 → 制作依赖」。选中配方后可查看模式权限、成品、原料标签、取得地点和工位解锁配方。双击配方条目可继续查看依赖。迁移后的工作台安装测试从炖食查到种植地和香料，并跟随炉灶依赖跳到造炉配方。

原创远征可声明版本为 1 的 `crew`，包含初始角色 `initial` 和角色表 `characters`。角色的 `heat_guard` 降低过热伤害，`venom_guard` 降低敌人的初始毒量。章节可用 `unlock_character` 解锁角色并用 `activate_character` 切换到该角色。站点的 `inspect` 为至多 120 字节的一行 UTF-8 台词，选中附近站点或查询快照即可查看。使用角色或检视新规则的 Windows 发行包声明 `expedition_character_format: 1`。

章节可用 `after_any` 声明 1–8 个备选前置章节，任一完成即可满足条件。原有 `target` 当前章节条件可继续同时使用。 `unlock_character` 记录新角色 ID。启用分支的项目按动作重放已完成章节和角色解锁，重复动作不发放奖励。文档载入时检查前置 ID 和依赖图。Windows 包需声明 `story_format: 1`。

## W29 权限与存档槽

方块协作服务端可选启用私网 TLS，凭邀请加入，凭原会话票据重连。回归在回环地址上运行两个真实 TLS 客户端，检查跨世界快照、服务重启后恢复、拒绝写操作和存档未改动。2026 年 11 月 23 日确认暂缺第二台同网设备，实体局域网连接登记为待验。 [服务端参数](../../examples/w15-lab/README.md#局域网运行与复跑)

远征可引用稳定 ID 为 `expedition-controls` 的数据资源。文件包含 `version: 1` 与 `bindings` 对象，每项覆盖一个动作，接受一个或两个键。例如 `"bindings": {"north": ["K", "Up"], "gather": ["M"]}`。接受大写英文字母、方向键以及 `Space`、`Tab`、`Period`、`Backspace`。解析合并后的键位需要唯一，存档菜单仍使用 F1、Esc 和数字键。播放器根据生效键位更新操作提示，`expedition.replay` 返回 `input_bindings`。键位文件独立于远征规则，原修订的存档可以在重映射后继续使用。Windows 发行包声明 `expedition_input_format: 1`。

本机服务端可以用 `--read-only` 打开已有的会话存档。持原票据的参与者可读取快照，加入新角色和执行写操作会分别返回 `ticket_required` 和 `permission_denied`。回归逐字节比较存档，确认只读会话不改动状态。 [独立服务端样例](../../examples/w15-lab/README.md)

Windows 发行包默认用第 1 槽及原存档文件名，可用 `--slot=2` 或 `--slot=3` 选择启动槽。游戏内按 **F1** 打开存档菜单，再按 **1**、**2** 或 **3** 切换。被占用或损坏的槽位会显示错误并保留当前进度。打开空槽会从初始状态出发，首次成功行动后自动保存。`--check-save=N` 只验证该槽。 [存档参数](../../examples/w25-lab/README.md)

2026 年 11 月 24 日，Windows 本机运行导出的风园。`verify.py --window-input` 将键消息投递给试玩包自己的隐藏窗口，实际通过播放器的按键、菜单和保存逻辑。回归确认原键位失效，按新键完成 13 个行动，坏槽保留原字节，关闭菜单后可继续，切回和重开仍能恢复各自存档。硬件键盘和第二台局域网设备的人工验收仍待执行。

可用 `interaction_priority` 在多个可达站点中优先选择一个。默认交互先按优先级，再按距离。显式指定站点时保留该目标。播放器的站点列表优先显示文档赋予高优先级的站点。使用此配置的 Windows 包需声明 `interaction_format: 1`。
