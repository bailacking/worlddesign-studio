# WDS 50 周开发计划｜最终版

**第 50 周交付目标**是 WDS 正式版，以及四项独立通过的实测。两款参考游戏各在 **30 分钟内从零资产完成复刻**，两道首次揭晓的原创需求各在 **60 分钟内**生成一款同等量级的游戏，分别是方块与非方块。每项都要当场交付**独立运行的成品和可由人继续编辑的 WDS 工程**。

原计划代码基线为 `main @ 5092c9c`。第 1 周从正式开工起算。50 周是冲刺目标，W4 已实测校准首批技术路线、剩余工作量及产能情景。 [周交付记录](roadmap.md#周交付记录) · [工期更新](w4-benchmarks.md#工期更新)

## 一、采用的提速方案

| 议题 | 采用的做法 |
|---|---|
| **内容生产** | 先写校验器，现场生成可编辑的项目脚本和生成器，由程序展开重复条目。把批量内容与独特规则、版本特例分开测，按失败条目局部修补。 |
| **交付顺序** | 第 8 周用第二台机器收首款小游戏，第 16 周收两个类型的共用流程。两款游戏并行，早测跨世界存档、红石和联机。资产、取证、AI 和跨平台从前半程贯穿。 |
| **质量核查** | 玩法和表现分别验收。进度覆盖率可用于诊断，正式通过取决于限时内封存的完整产物。原创采用盲题。 |
| **产能核算** | 以已验收的产出估算交付，登记接口等待、返工和复核。第 4 周更新工作量、关键路径和日期区间。 |

## 二、最终验收口径

| 目标 | 通过条件 |
|---|---|
| **30 分钟复刻《我的世界》** | 固定 **Java 1.16.5** 客户端与服务端。覆盖主世界、下界、末地、种子与结构、方块状态、物品配方、生物与村民、红石、游戏模式、指令与数据包、界面及局域网和独立服务器玩法。W2 按发起人确认采用独立复刻，以 WDS 客户端、独立服务端与存档实测。 [方块验收基准](voxel-benchmark.md) |
| **30 分钟复刻《饥荒》** | 覆盖 **PC 单机原版＋巨人国＋海难，截至 2016 年 12 月 31 日正式发布的内容**，包括角色、台词、冒险、洞穴遗迹、四季、航海、火山和当时支持的跨 DLC 旅行。W2 取得 `198251` 的 [Klei 发布证据](https://kleiforums.com/game-updates/sw/198251-r159/)，可运行版本待补证。 [饥荒验收基准](dontstarve-benchmark.md) |
| **60 分钟原创方块与非方块游戏** | 分别使用独立验收人首次揭晓的需求。用参考规模制定评分表，涵盖内容、世界、独立机制、跨系统联动、成长、稳定性和可编辑性。题目各含一项未演练的规则组合。按需求及同量级评分表验收。 |
| **实质内容与表现** | 为每项记录版本、触发条件、原版结果、WDS 结果和证据。确定性规则对比数值、时序和状态，随机规则用固定种子或预先约定的统计方法。材质贴图允许略有区别，仍核对辨识度、碰撞轮廓、动画和操作提示。音乐音效在 W4 用样本约定相似度。冻结范围内要求**零缺项、零已知实质偏差、零关键缺证**。 |
| **WDS 核心要求** | 默认安装完成创建、导入、编辑、试玩、保存重开、导出和交接。GUI、CLI 与 AI 共享项目操作；项目是可携带的普通文件；代码与可视化在声明子集内往返；插件可替换、禁用、卸载和恢复；AI 可换模型、限权、控预算、暂停和接管。2D 与 3D 共用创作流程。计划覆盖 Windows、Linux、macOS 原生工作流、Git 基础协作、插件 SDK 和发行验证。Web 验收含游戏试玩，以及 Web 编辑、远程宿主的可行性证据。 [产品范围](../product/scope.md) · [平台规格](../architecture/platforms.md) · [版本管理](../architecture/version-control.md) |

### 零资产、计时与人工接手

- **开跑前**封存 WDS、通用插件及工具、模型配置和机器环境。预装能力须能服务无关原创项目。目标游戏专用贴图、模型、音乐、地图、成品规则、内容包、预写生成器和缓存产物均为空。允许在计时内查阅声明过的参考来源并编写项目脚本和生成器。评测端保管完整预期结果，向生成端返回具体失败信息。
- **收到需求即计时**。查询、生成、导入、修补、等待、最小运行检查、打包和交接全部计入。停表时交付成品、源工程、清单和产物校验值。长局、联机、覆盖和人工审核可以在停表后用封存产物执行。停表后修复的版本须重新计时。
- **交接单独验收**。创作者改一项内容和一条规则，保存重开、重新试玩和导出，另一台干净机器运行新成品。记录实际用时、输入输出 Token、等待、失败重试和人工干预，并保留同模型无 WDS 的对照。
- **发行核对权利**。WDS 和公开示例使用可分发内容。复刻的内部验收和参考成品公开分发分别签收，保留生成过程和素材来源。 [Minecraft EULA](https://www.minecraft.net/en-us/eula) · [Klei 创作指南](https://support.klei.com/hc/en-us/articles/360029880791-Player-Creation-Guidelines)

| **46** | 用新需求盲测两款原创，验证玩法变化、同量级、画面和声音完整度。 | 方块、非方块各独立通过 60 分钟，验收人按需求试玩并改内容和规则重出成品。 |
| **47** | 第三方从干净安装体验创建、混合编辑、AI、换插件、恢复一次故障和导出。 | 对照核心产品条目、两类创作过程和第三方插件接入。问题定位到界面、文档或能力。 |

| **50** | 签收 WDS、支持平台安装包、公开示例、四项产物、操作证据和覆盖报告。 | 30／30／60／60 四项、核心平台、净环境和人工续编分别判定。未达目标列明差距与复验条件。 |

## 四、执行与共同调研

每周认领记录范围、依赖、交付物和验收步骤。用一次真实操作和检查结果签收。任务沿用 [任务编号与并行约定](parallel-delivery.md)，遵循 [长期维护与验证](../engineering/quality.md)。架构、接口、关键实现、复杂排错与最终验收由 Codex 负责。仅当低判断任务能独立验收且明显节省额度时，由 Codex 给出短提示，发起人选择是否手动派发。

上一轮较小范围的估算为 625～1,215 个等效工程日。W4 已根据内容、资产及后端试验更新近期工作包，并把两款参考和四项正式验收纳入全量估算。剩余工作量和按有效开发线换算的日期见 [W4 工期更新](w4-benchmarks.md#工期更新)。每两周用已验收产量复核。关键依赖失效或连续两期明显落后时，提交差距、提速办法和各自后果，继续可独立推进的工作。交付日期、范围和正式门槛的改变由发起人决定。
