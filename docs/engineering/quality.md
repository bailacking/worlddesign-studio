# 质量与验证

## 当前自动检查

GitHub Actions 的 `Repository checks` 在提交到 `main` 和面向 `main` 的 PR 上运行。它检查 Python 工具的静态规则与格式、Markdown 本地链接目标、离线架构页的外部资源声明与页内锚点，以及内联 JavaScript 语法。页面交互与布局另行实测。

在仓库根目录复跑相同检查。需要 Python 3.14 和 Node.js 22，建议在 Python 虚拟环境中安装：

```sh
python -m pip install -r scripts/requirements-quality.txt
python -m ruff check scripts
python -m ruff format --check scripts
python scripts/check_docs.py
```

C++ 在同一工作流配置了 Linux 的编译、CTest、clang-format 和 clang-tidy 检查。Windows x64 的 Debug 和 Release 构建各通过五项测试，覆盖工具链、插件宿主、资源改名、方块世界与规则操作。命令见 [开发指南](development.md#构建与测试)，Linux CI 尚待运行。

## 证据要求

以下各层用于验收引擎实现。每项结果记录版本、配置、环境、任务、预期、实际结果、失败与限制。文档检查、代码检查、构建、运行和可玩性分别验收。

## 验证层次

| 层次 | 核心检查 |
| --- | --- |
| 公共契约 | 输入输出、版本、错误、权限、取消和资源归属 |
| 操作一致性 | GUI/CLI/AI 对同一修订执行等价任务，结果一致 |
| 插件生命周期 | 初始化失败清理、依赖管理、禁用与卸载、更新与恢复 |
| 默认组合 | 固定版本、支持平台、完整基础工作流及回退路径 |
| 资源与编辑 | 编号引用、多形式往返、并发冲突、缓存重建与迁移 |
| 游戏闭环 | 实际交互、保存重开、规则修改和独立运行 |
| 发行 | 安装升级、平台支持、打包内容和第三方声明 |

## 插件故障矩阵

至少覆盖缺依赖、循环依赖、版本不匹配、重复能力、导入失败、同步或异步初始化失败、无效配置、任务取消、资源释放失败和迁移失败。区分可选能力与必需能力：前者需要可解释的降级，后者不能被误报为整体就绪。

验证保存配置与当前生效配置的一致性、需重启状态、更新失败后的实际安装内容以及恢复失败提示。不能只检查清单文件恢复成功。

兼容性测试优先覆盖契约、默认组合、高风险组合和已知冲突复现。发布报告明确覆盖范围，不声称穷尽任意组合。

## 资源与逻辑

Windows x64 的 C++ 集成测试验证了 GUI 和 CLI 的清单及源字节一致。测试覆盖清单暂存失败回滚、重开时恢复旧修订或保留新修订、重复重开，以及路径冲突时保留文件。重开用例通过预置文件复现中断状态。断电持久性不在当前验收范围内。

检查改名、移动、复制、重复编号、跨项目导入及删除恢复；验证文本、结构化与二进制冲突。对逻辑可互转子集做行为等价与往返保存，对不支持的表达确认提示与原始资料保留。

## 游戏与 AI

首个沙盒执行进入世界、移动、方块交互、保存重开、AI 修改与恢复。AI 任务记录成本、人工接管、错误和运行证据，避免只挑选成功案例。自动生成的测试结论需要与实际执行记录对应。

方块世界测试覆盖地面、墙体碰撞、跳跃落地、放置与破坏、禁止在玩家位置放置，以及存档往返。另在 Windows 启动实际窗口，用隔离的存档目录触发破坏和保存，再重开确认结果，验证坏档未被覆盖。键鼠手感和帧率尚未实测。

模板交接测试创建两个独立项目，验证中文和空格路径、同名目录拒绝覆盖及规则隔离。在 Windows 实际窗口打开命令行创建的项目，用 F6 将跳跃速度从 8 改为 9，命令行读取到 9。存档留在该项目内，另一个项目和默认存档目录不受影响。

内容预设测试验证两套配置的天空颜色、破坏规则与放置类型影响运行结果，重开地形保留内容配置。在 Windows 窗口用 F7 将台地项目的默认放置材料改为草地，命令行读回，草地项目保持原样。一次本地创建并读取两个项目耗时约 0.07 秒，仅计工具执行时间。完整创作耗时与 Token 尚未测量。

Release 目录通过外部 Agent 命令行预览 `6 → 8`、应用、启动沙盒并保存，然后恢复 `8 → 6` 并再次启动。单独测试规则变更会影响实际跳跃、过时请求会被拒绝。此验证在开发机使用隔离的存档目录完成，兼容性和性能还需在其他机器实测。

性能报告包含设备、运行配置、资源规模、测量过程与波动。原型建立前不预填达标数值；跨平台结果逐平台记录，不以模拟或编译替代完整运行验证。

## 文档与发布质量

文档应与能力状态一致，来源可复核，本地引用有效。对外发行前验证许可、打包范围、迁移和恢复说明；检查公共入口与联系人实际可用。尚未具备证据的事项明确列为限制。
