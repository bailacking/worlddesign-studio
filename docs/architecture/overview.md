# 系统架构

## 架构目标与状态

WDS 采用插件驱动的设计方向，由精简运行基础连接创作工具、项目服务与游戏运行能力。本文是概念架构，尚未形成运行实现；语言、框架、协议与进程边界正在评估。

整体架构自主设计，同时复用适合的成熟组件。复用可以发生在库、服务、工具或现有引擎适配层，具体粒度由实验与许可评估决定。

## 分层与依赖方向

```text
人类与 AI
    │
图形界面 / 命令行 / AI 适配入口
    │
共享操作与项目状态
    │
能力契约 ── 运行基础：生命周期、依赖、组合、诊断、恢复
    │
创作插件 / 项目与资源服务 / 游戏运行插件
    │
源文件与资源数据 ── 构建处理 ── 游戏资源与运行依赖
```

图中表达职责与依赖，不代表每层必须是独立进程或单独软件包。具体能力的接口定义、实现与调用方应可分别识别；调用方依赖公开契约，不直接操作其他插件的内部结构。

## 模块职责

| 部分 | 责任 | 不应承担的责任 |
| --- | --- | --- |
| 运行基础 | 启动与生命周期、能力发现、依赖计划、最低限度诊断与恢复 | 垄断所有创作业务或固定唯一实现 |
| 操作与状态 | 参数、权限、修订、变更与结果；长任务和取消 | 为每个界面分别维护业务规则 |
| 项目服务 | 资源身份、路径、依赖、源与派生资料、索引 | 将自动摘要当作原始内容的替代 |
| 创作插件 | 场景、代码、逻辑图、资源工具、AI 与版本协作 | 通过未公开路径修改其他能力 |
| 运行插件 | 渲染、物理、输入、音频、动画与网络 | 隐式依赖编辑器界面或开发凭据 |
| 组合与发行 | 明确插件版本、配置、平台、验证范围和恢复入口 | 用发布者身份替代兼容性证据 |

## 控制流与数据流

控制流从创作入口进入共享操作，完成参数、授权及前置修订校验，再分派到能力实现。数据流以项目源材料和资源身份为基础，形成可重建索引、预览与目标平台产物。编辑器显示操作结果与诊断，AI 使用同样可检查的状态继续任务。

持久变更、临时进度和运行观察应分开表达。重要操作需要保留资源身份、修改前后修订、调用来源、结果与恢复关联；不能据此假定游戏状态全部采用事件溯源，逐帧数据是否记录应按成本和用途决定。

## 部署与边界

编辑器宿主、游戏运行时、独立构建任务和外部 AI 服务拥有不同生命周期与权限。插件声明所属环境；共享逻辑不意味着共享全部进程状态。分层配置应能解释最终选择了哪些插件、哪个设置覆盖了哪个设置，以及哪些变更需要重启。

同进程原生能力与跨进程服务的边界尚未确定。性能路径可研究进程内实现，高风险或低频能力可研究受限制的执行环境；所有保证必须对应实际实现与测试。
