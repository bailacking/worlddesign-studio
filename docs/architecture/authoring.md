# 逻辑与编辑器

## 创作入口

WDS 同时提供代码与可视化逻辑编辑，允许根据任务和经验选择或混合使用。图形编辑器面向场景、资源和行为组织，命令行与 AI 可通过共享操作完成相应任务。首版界面布局见 [桌面工作台](workbench.md)，脚本语言和图形表达形式仍待选型。

### 桌面工作台

通用项目的桌面入口是 Qt Widgets 工作台。它通过共享项目服务支持创建、打开、场景编辑、试玩、整数数据字段预览和恢复。工作台按需构建，默认核心和 CLI 不依赖 Qt。各平台的实测范围以发布规格为准。 [桌面工作台](workbench.md) · [平台与交付](platforms.md)

## 共同语义基础

两种逻辑编辑方式应共享行为语义和运行依据，避免维护互不一致的执行规则。可研究共享中间表示、统一行为模型或其他实现路线；具体数据结构与编译路径待实验评审。

应明确可互转的表达子集、执行顺序、数据类型、状态和错误语义。代码中无法可视化的部分需要保留原始表达或使用明确的扩展节点；不能承诺任意代码都可无损转换成节点图。

## 编辑、运行与调试

编辑修改经共享操作写入项目，运行时读取有效的行为模型。应能从运行错误定位到代码位置或可视化元素，并显示资源身份和相关修订。断点、状态观察、撤销和重做的具体范围由实现阶段规定。

场景、逻辑图与资源面板不应分别保存互不约束的业务副本。编辑器插件的注册和释放遵循插件生命周期；项目关闭后应释放后台任务、监听和临时资源。

## 信息保留与版本变化

模型迁移应保留用户表达和无法识别的扩展数据，无法安全迁移时拒绝覆盖。生成代码、手写代码和图形表示的权威关系需说明，不把一次代码生成称为双向同步。

## 验证标准

用同一小型玩法分别完成代码创作和可视化创作，比较行为结果。对声明支持的子集做往返编辑、保存重开与调试定位；对不支持的表达检查提示及原始资料保留；验证混合修改后的冲突与恢复。
