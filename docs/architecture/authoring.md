# 逻辑与编辑器

## 创作入口

WDS 同时提供代码与可视化逻辑编辑，允许根据任务和经验选择或混合使用。图形编辑器面向场景、资源和行为组织，命令行与 AI 可通过共享操作完成相应任务。首版界面布局见 [桌面工作台](workbench.md)。W11 实现首个规则语言和节点图文件格式。

### 桌面工作台

通用项目的桌面入口是 Qt Widgets 工作台。它通过共享项目服务支持创建、打开、场景编辑、试玩、整数数据字段预览和恢复。工作台按需构建，默认核心和 CLI 不依赖 Qt。各平台的实测范围以发布规格为准。 [桌面工作台](workbench.md) · [平台与交付](platforms.md)

## 共同语义基础

W11 的代码和节点图 v1 共用有序行为模型。一个场景保存当前选用的表示，其中参数和状态定义在同一命名空间。运行时加载、校验和执行经过同一实现。两种表示间的转换由 `behavior.convert` 提供，输入与输出均可由命令行和 AI 使用。

- `param 名称 整数` 声明只读参数，`state 名称 整数` 声明初始状态；都可在定义前引用，名称用小写字母开头，随后可含小写字母、数字和下划线，最多 32 字符。
- `on start set speed step` 在开始或重新试玩时触发。`on tick if speed < cruise add speed step` 在每个固定步进的移动前触发。每个事件内按源顺序执行，后续规则读到前一条的更新。
- 每条规则可以有一个条件，比较支持 `==`、`<` 和 `>=`。条件两侧及更新右侧可以用状态、参数或整数。更新支持 `set` 和 `add`，目标必须是状态。整数为有符号 32 位，增量溢出时饱和到上下限。
- 节点图为 `{"version":1,"nodes":[...]}`。数组顺序定义执行顺序；声明节点用 `type`、`name`、`value`，规则节点用 `type:"rule"`、`event`、可选 `when:{left,op,right}` 和 `then:{op,target,value}`。字符串操作数引用名称，整数是字面量。
- 代码的空行、`#` 行和无法转换的行分别以 `comment` 或 `opaque` 节点保留原始文本及换行。支持的语句以规范格式输出。遇到 `opaque` 节点时，试玩报 `unsupported_behavior` 并定位到代码行或图节点。文档最多 256 节点、64 KiB 代码文本。

## 编辑、运行与调试

二维场景可选填 `behavior`，包含 `format`（`code` 或 `graph`）和 `document`。可用 `bind_vx` 将状态绑定到普通实体的横向速度，运行时值限制在场景速度范围内。试玩的 `behavior_state` 输出可观察当前状态。更新整份行为使用共享操作 `scene.restore`，校验项目修订和原场景字节后写入。工作台在本周可运行行为，图的内容通过 JSON 编辑。

场景、逻辑图与资源面板不应分别保存互不约束的业务副本。编辑器插件的注册和释放遵循插件生命周期；项目关闭后应释放后台任务、监听和临时资源。

## 信息保留与版本变化

模型迁移应保留用户表达和无法识别的扩展数据，无法安全迁移时拒绝覆盖。生成代码、手写代码和图形表示的权威关系需说明，不把一次代码生成称为双向同步。

## 验证标准

用同一小型玩法分别完成代码创作和可视化创作，比较行为结果。对声明支持的子集做往返编辑、保存重开与调试定位；对不支持的表达检查提示及原始资料保留；验证混合修改后的冲突与恢复。
