# 社区治理

## 原则与阶段

WDS 采取开放协作方向，所有人都是贡献者与使用者，不设置官方与个人开发者的身份等级。维护权限承担审查、兼容性、发布与用户保护责任，不是个人价值或插件质量排名。

项目处于筹备阶段，以下为治理框架；领域维护者、发布团队和私密举报渠道尚待建立。

## 角色与责任

| 角色 | 责任 |
| --- | --- |
| 发起人与协调者 | 维护愿景、解释产品目标、组织讨论与交接 |
| 贡献者 | 设计、实现、调研、测试、文档和体验反馈 |
| 领域维护者 | 审查所属领域，维护契约、兼容性和公开说明 |
| 发布维护者 | 根据明确版本、许可和验证证据执行发行 |
| 社区规范处理人 | 接收私密报告、保护当事人、回避冲突和处理申诉 |

WDS 由王大帅发起。领域与发布职责应在实际有人承接时公布，不将筹备框架描述成已运作的组织。

## 设计评审

小范围文字修正可由相关维护者说明理由后采纳。架构、数据格式、插件契约、许可或重大路线调整需要明确的问题、候选、证据、影响与迁移方案，并给相关参与者表达异议的机会。

结论进入所属主题文档，评审意见与采纳理由留在相应议题或变更说明。产品判断和技术判断应建立在可理解的选项与实验上，不能以缺少专业知识为由要求任何人批准无证据的技术结论。

讨论期限、表决条件、资格、法定人数和僵局处理机制将在社区规模需要时明确，不预设未经实践的固定席位或永久否决权。

## 权限与交接

维护职责依据持续贡献、审查质量和责任承担授予，公布范围与理由。退出或职责变化时交接开放问题、接口、发布状态与访问权限；私密凭据不写入公开文档。必要时缩小或移交权限，保持过程可解释。

## 插件生态

插件受欢迎程度由用户评价和实际体验体现。默认组合依公开的任务覆盖和兼容性标准维护，其他插件可提供同等或更合适的替代。评分、权限、兼容性与安全报告分别展示，不能把高星视为安全保证。

发现与排序规则应透明，刷分和恶意报告的处置应有证据和申诉路径。不得因插件来自某团队而人为赋予更高评价，也不得因合理批评而惩罚贡献者。

## AI、透明与隐私

AI 可以参与创作和审查辅助，实际提交者与维护者负责核对结果及权限。AI 不自动取得维护权或表决权。重要规则、已知问题与发行证据应公开，举报材料、个人信息和凭据应保护。

未来资金、赞助、商标或商业服务安排需要独立说明利益冲突与责任，不暗示当前已有基金会或商业承诺。
